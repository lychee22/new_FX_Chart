# FXCOR Chart 需求管理

需求的**唯一事实来源**。凡是要做的事，先在这里落成一条带 ID 的记录，再谈实现。

## 需求来源（两类）

| 类型 | 特点 | 例子 |
|---|---|---|
| 外部输入（少数） | 领导 / 产品 / 用户提出，优先级通常最高 | "周三要能横屏，给领导演示" |
| 自主发现（多数） | 自己发现问题、自己解决 | 自测发现删除白屏；副图交互混乱；性能卡顿 |

> **自主发现是主要来源**，所以这套机制的核心是**帮你排优先级**——自己发现的东西多且杂，容易东一下西一下。总表让你每周末都能看到"哪些重要的事还没做"，而不是被最近想到的事牵着走。

## 记录分两级（为了轻，记了才会用）

| 级别 | 时机 | 做法 | 耗时 |
|---|---|---|---|
| 一级 | 想到 / 发现就记 | 只在下方总表加一行 | 30 秒 |
| 二级 | 确定要开始做 | 建 `REQ-XXX-NNN.md` 详情 + 总表改状态 | 2 分钟 |

自主发现的"想法"先用一级记着攒起来；确定这周要做，再升二级。**不要对每条都建详情文件，那样会懒得记。**

## 需求状态

只有 4 种，改状态 = 改总表里一行 + commit：

| 状态 | 含义 |
|---|---|
| 待办 | 已记录，未开始 |
| 开发中 | 正在做 |
| 已完成 | 按验收标准交付 |
| 已取消 | 不再做（写明原因） |

## 需求 ID 规则

`REQ-模块-NNN`，模块用英文单词，序号从 001 递增：

| 模块 | 含义 |
|---|---|
| PANE | 副图（pane） |
| TOOL | 绘图工具 |
| UI | Toolbar / 视觉 |
| MOBILE | 移动端 |
| PC | PC 端修复 |
| INTEG | 接口对接 / 集成 / 联调 |

## 使用方法

1. **随手记（一级）**：发现 / 想到一个需求 → 总表加一行，标类型（外部/自研）→ 完。不用 commit，攒着。
2. **要做了（二级）**：用 `_template.md` 建详情文件 → 总表状态改 `开发中` → commit `docs: REQ-XXX-NNN 开发中`。
3. **做完**：代码 commit message 带 ID，`feat: 完成 REQ-MOBILE-001 横屏模式`——需求和代码同一次提交，可追溯。
4. **每周初**：过一遍总表，挑 3~5 条 P0/P1 定为本周焦点，其余排队；周报直接从本周完成项生成。
5. **外部需求（口头等）**：当场记，升二级，标类型"外部"。

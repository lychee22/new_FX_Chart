# 前端问题记录

> 用途：记录本前端项目排查、解决过的疑难杂症，沉淀根因和可复用解法，避免重复踩坑、重复调研。
> 范围：UI、交互、兼容性、性能、构建打包、数据状态、接口等一切值得复用的前端问题。

## 1. 记录规范

### 1.1 记录价值判断（每次记录前必查）

满足以下任意一条，就值得记录：

- 排查耗时较长（超过 30 分钟），或结论涉及框架源码、组件库内部实现、浏览器/系统差异；
- 同类问题换设备、换浏览器、换数据、换版本后可能再次出现（跨端兼容、时序、缓存、资源释放等）；
- 解决方案带有取舍或隐藏约束（如 `!important`、禁用某个能力、修改全局配置），不写下来容易被后人误删误改导致复发；
- 修复需要多文件联动，或改动公共样式、公共组件、构建配置，回归面较大；
- 现象和根因不直观，重新搜索资料也要花不少时间（如 iOS 自动缩放、antd CSS 优先级）。

不值得记录：一次性拼写错误、笔误、纯格式调整，或仅当前需求私有且确定不会再出现的值。拿不准时记录，控制篇幅即可。

### 1.2 必填与详略标准

每条记录必填四个部分：**问题描述、问题定位、解决方案、解决后提升效果**。
按需补充：触发条件/复现步骤、关键代码、取舍说明、通用性避坑、验证方式、关联 commit。

- 简单修复：一段话加少量代码即可；
- 跨端、框架级或容易复发的问题：保留完整根因、复现步骤和避坑点；
- 记录里必须包含后人能“照着搜到”的关键词：设备、浏览器、库名、现象、根因。

### 1.3 分类

| 分类 | 适用场景 |
| --- | --- |
| UI 界面问题 | 样式、布局、图标、文案显示、交互表现 |
| 兼容性问题 | 浏览器、移动端、操作系统、WebView 差异 |
| 性能优化问题 | 渲染、加载、内存、首屏、卡顿 |
| 构建打包问题 | Vite/webpack、依赖版本、产物、部署 |
| 数据与状态问题 | 状态同步、数据一致性、刷新/缓存 |
| 接口与网络问题 | 请求失败、超时、并发、鉴权 |
| 安全与权限问题 | XSS、CSRF、敏感信息、摄像头/定位等权限 |
| 其他 | 无法归入以上分类的问题 |

分类可以在使用中补充，但新增分类前先确认是否已有更合适的归类。

### 1.4 状态约定

- `已解决`：修复已生效，并至少完成一次验证；
- `待验证`：已有修复方案，尚未在目标环境验证；
- `有隐患`：问题缓解但未根治，或方案带副作用，需要后续跟踪。

### 1.5 维护流程

1. 解决问题后趁上下文还在时记录，编号递增（001、002、003……）；
2. 按模板填写，并同步更新“目录索引”；
3. 修复方案带取舍时，在记录中明确写“不要随意移除/调整”的原因；
4. 每周或每次发布前扫一遍索引，把 `待验证`、`有隐患` 的记录单独过一遍；
5. 记录只追加、不删除，过时或已失效的内容标记“已过时”，保留历史脉络。

## 3. 问题记录

### 001 iOS Safari 点击输入框自动放大

- 日期：2026-08-07（首修 2026-08-06，当日补充优先级修正）
- 分类：兼容性问题
- 状态：已解决
- 影响范围：移动端指标设置面板（Select/InputNumber）、图表文本框（contentEditable）编辑态
- 相关文件：`src/styles/main.css`、`src/styles/TextBox.css`

**问题描述**

iPhone 上打开图表后，点击“设置”面板里的指标下拉框或参数输入框、点击图表文本框进入编辑时，页面会自动放大；输入完收起键盘后页面仍停留在放大状态，用户需要手动缩回，交互割裂。

**问题定位**

- 根因 1：iOS Safari 在聚焦 `<input>`、`<select>`、`<textarea>`、`contentEditable` 时，如果输入元素计算字号小于 16px，会判定内容过小，自动把页面放大到 1.x 倍。本项目没有禁用页面缩放，因此触发了该默认行为。
- 根因 2：antd v5 的 Select 搜索输入框通过 cssinjs 注入 `font-size: 14px`，且样式优先级高于业务里普通的 16px 覆盖，第一次只写 `font-size: 16px` 无效；InputNumber 输入框也需要一起统一处理。
- 根因 3：图表文本框（contentEditable）桌面编辑态字号为 12px，在触屏设备上同样会触发 iOS 自动缩放。

**解决方案**

在移动端设置面板内，对 Select 选择器、Select 搜索输入框、InputNumber 输入框统一强制 16px：

```css
/* src/styles/main.css */
.mobile-settings-panel .ant-select-selector,
.mobile-settings-panel .ant-select-selection-search-input,
.mobile-settings-panel .ant-input-number-input {
  font-size: 16px !important;
}
```

文本框只在触屏设备编辑态提升到 16px，桌面视觉不变：

```css
/* src/styles/TextBox.css */
@media (pointer: coarse) {
  .lw-textbox--editing {
    font-size: 16px;
  }
}
```

不修改 viewport 的 `user-scalable=no` / `maximum-scale=1`，保留用户手动缩放能力（无障碍考虑）。

**解决后提升效果**

- iOS Safari 中点击上述输入控件不再自动放大，输入完成后页面保持原缩放比例，移动端设置和文本批注操作恢复正常；
- 桌面端编辑态字号未变化，图表批注视觉无回归；
- 保留了双指缩放能力，没有牺牲可访问性。

**通用性/避坑**

- 移动端输入控件字号小于 16px 时，iOS Safari 在聚焦时自动放大是跨项目通用规则，排查优先级高于禁用 viewport 缩放；
- 组件库 CSS-in-JS 注入的样式可能覆盖业务样式，出现“写了不生效”时要检查实际注入规则和优先级，必要时使用 `!important`，并在注释里写明原因，防止后续被清理；
- 不要用禁用手势缩放来绕开，会损害无障碍和用户体验；
- 排查同类问题优先检查：输入框实际计算字号、是否为 contentEditable/textarea、页面是否允许缩放。

**验证方式**

- 真机 iPhone + iOS Safari：依次点击设置面板下拉、参数数字框、图表文本框编辑态，确认聚焦无放大、关闭键盘后页面比例不变，双指缩放仍可用；
- 桌面 Chrome：打开文本框编辑态，确认字号仍为 12px，无视觉变化。

**关联**

- 首次修复 commit：`b7ebbc70 fix(mobile): 防止触屏输入自动缩放`
- 2026-08-07 补充：antd Select 搜索框需要 `!important` 才能覆盖 14px（`src/styles/main.css`）
